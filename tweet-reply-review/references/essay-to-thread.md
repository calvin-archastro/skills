# Essay → thread (how to transform)

One home for convert-mode craft. SKILL.md decides *when* this runs; this file is *how*.

For You ranks **tweet 1 only**. Everything after is a self-reply. Write 1/ like it's the only post. Write 2/… for people who already tapped.

## 1. Don't serialize

Never wrap the essay into tweet-sized paragraphs in order. That's a blog with numbers.

Do this instead:

1. Underline the **one sentence you'd argue about**. That's 1/. Not the intro, not the abstract.
2. List the essay's beats. Keep a beat only if it **changes the claim**, **gives something to steal**, or **is the honest limit**. Cut setup, literature review, "as I mentioned," restated conclusions.
3. Order beats so each tweet *needs* the previous one. If 4/ still makes sense after deleting 3/, 3/ is fat — cut it.
4. Last tweet is the **ask implied by the essay**, not "thanks for reading."

Target **4–8** tweets. Hard cap **10**. Extra chapters die.

## 2. Pick a spine (one)

Match the essay's actual shape. Don't force pain→ship onto a taxonomy.

| Essay is… | Spine | 1/ is… | Middle is… | Last is… |
| --- | --- | --- | --- | --- |
| An argument | Contrarian + Ask | The fight | Why the default is wrong | "Ask." / prove me wrong |
| A how-to / FAQ | Gift dump | "Nth time I was asked X" | Numbered recipe | Link + what breaks for you |
| A classification | Taxonomy | The 2–4 buckets | One tweet per bucket | "Where do you sit?" |
| A ship / build story | Pain → ship | The pain, one metaphor | Mechanism + limit | Try / roast the repo |
| A confession | Tension | I hate X / still do X | The story, short | Anyone else? |

If two spines fit, write both (that's the two candidates in convert mode). Rank them. Print one.

## 3. Write each tweet (not chopped prose)

Each tweet is **one spoken beat**. One idea. Period.

- **1/** — claim + stake in their voice. Must work if nobody taps. Banned openers: "A few thoughts on…", "Thread 🧵", "I've been thinking…", the essay's first paragraph.
- **2/** — the mechanism or the first proof. Start mid-thought if their voice does; don't recap 1/.
- **Middle** — one beat. Example, number, named thing, or limit. Not two.
- **Last** — a reply someone can type in one line.

Line rules:

- Prefer their live length (from the fetch). If they write short captions, don't emit 280-char walls.
- One linebreak is fine; essay paragraphs are not.
- Drop essay glue: *Furthermore, In this section, As discussed above, It is important to note.*
- Keep proper nouns, numbers, and honest limits from the source. Don't invent a repo, metric, or villain.
- Caveats get **one** tweet, not a hedge on every line.

## 4. What to cut (always)

- Background the audience already has
- Second examples of a beat you already posted
- Process diary ("first I tried X, then Y") unless the failure *is* the point
- Soft endings ("more soon", "hope this helps")
- A leftover section turned into tomorrow's original — that's a burst

## 5. Quick check before you print

1. Can someone reply to **1/** without reading the rest?
2. Can someone reply to the **last** tweet in one line?
3. Delete any tweet and the thread still tracks? That tweet was fat — it's gone.
4. Would *they* say this out loud this week? If it sounds like the essay's narrator, rewrite it in the fetch voice.
